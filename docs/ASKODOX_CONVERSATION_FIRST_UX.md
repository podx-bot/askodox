# ASKODOX Conversation-First UX — Locked Direction

## Core principle
ASKODOX is an AI assistant first, not an ecommerce/category-first app. The user should be able to state any need naturally by text or voice. ASKODOX understands the request, preserves already-known details, asks only for information still required for a useful match, shows the understood requirement for confirmation/change, then performs real-time matching/comparison.

## Primary journey
Home → Natural request → Understand intent/constraints → Ask only missing details → Requirement/Deal Card → Confirm or Change → Real-time matches/comparison → Continue conversation / connect / close deal.

## Home
- Clean AI-assistant opening.
- Small ASKODOX mascot/identity.
- Main Ask field with voice + text.
- A small set of quick intents only; no marketplace wall.
- Quick intents are shortcuts into the same Universal Deal Brain, not separate brains.
- Explore is secondary discovery.

## Universal Deal Brain
Normalize text and voice into one persistent deal state. Capture what is relevant, including intent, item/service/job/ride/financial need, budget/price, quantity/unit, variant/quality/model, location/distance, timing, availability, pickup/delivery/remote and category-specific fields. Merge conversation turns. Never re-ask a known detail unless it conflicts or needs confirmation.

## Dynamic clarification
Questions are category-aware and missing/conflict-only. Example: product can ask budget/location; job can ask skill/location/remote preference; ride can ask route/time; service can ask service/location/time; loan/insurance can ask only necessary eligibility/comparison details.

## Requirement confirmation
Before matching when needed, show a concise structured card: what ASKODOX understood, what is known, and any unresolved critical detail. Provide Confirm and Change actions.

## Search / Explore
Search/Explore is the full-power discovery surface, not the primary intelligence layer. It can expose Buy/Sell, Jobs, Services, Rides/Travel, Loans, Insurance, Credit Cards, Utilities, Real Estate, Education, Health and future categories. Selecting a category seeds the same Deal Brain.

## Matching and comparison
Return genuine available matches based on the confirmed requirement. Comparison adapts by domain: products can compare offline/local vs online plus distance/savings; jobs compare fit/pay/distance/remote; services compare availability/price/distance; rides compare route/time/fare; finance/insurance compare appropriate eligible provider/offer attributes.

Distance scope should be contextual, e.g. Near me / city / state / India / anywhere / online, or 1 km / 5 km / 25 km / 100 km / any distance where useful.

## Monetization / attribution
User usefulness and relevance come first. Eligible partner journeys may use tracked lead/deal/click IDs, affiliate/deep links, provider references and conversion callbacks so ASKODOX can attribute commissions for commerce, insurance, loans, credit cards and partner services. Commission size must not silently determine the best result. Sponsored/partner placements must be distinguishable where required.

## Functional rule
Every visible button must perform a real action or route to a functioning flow. Voice/text, quick actions, category shortcuts, comparison, confirm/change, save/resume and match actions must not be decorative.

## Approved UX character
Dark premium ASKODOX visual language; conversational and uncluttered Home; intelligence before categories; real-time deals/matches after understanding the requirement; persistent conversation/deal state; save and continue later.

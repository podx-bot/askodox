# ASKODOX Universal Home Dashboard — Approved Direction

## Opening screen
- Keep the dark navy/purple ASKODOX visual language.
- Reduce mascot size substantially so the functional content is visible without excessive scrolling.
- Remove the large tagline block from the opening area.
- Keep ASKODOX AI brand, Ask bar, mic and send actions prominent.

## Immediate quick actions
The first-row actions remain:
- Buy nearby
- Sell something
- Find work
- Book a service
- Find a ride

Each action must start the corresponding Universal Deal Brain flow immediately. The chip label must never be stored as the actual product, skill, service or route.

## Universal comparison layer
Comparison is not limited to commerce. The same comparison pattern must adapt by vertical.

Examples:
- Products: offline vs online, price, stock, distance, delivery.
- Jobs: nearby vs remote/anywhere, salary, location, timing, employer fit.
- Services: provider price, distance/service radius, availability, rating/fit.
- Rides/travel: route, fare, time, seats, pickup/drop options.
- Loans: provider, interest/EMI, eligibility, fees, tenure.
- Insurance: premium, cover, exclusions/benefits, provider eligibility.
- Credit cards: fees, rewards, eligibility, benefits.
- Utilities: bill/recharge/service options and savings where available.

## Offline market distance comparison
Offline is not only the nearest shop. ASKODOX should support user-selectable scopes such as:
- Near me
- 1 km
- 5 km
- 25 km
- 100 km
- Wider area / anywhere practical
- Online

The UI should show the trade-off between distance and savings so the user can choose whether travelling farther is worth the lower price.

## Explore ASKODOX
Home must clearly communicate that ASKODOX is broader than Buy/Sell.

Primary discovery groups:
- Buy & Sell
- Jobs & Work
- Services
- Travel & Rides
- Money & Loans
- Insurance
- Bills & Utilities
- Credit Cards / Financial Services
- Real Estate
- Education
- More / future categories

## Search scope
Use context-aware scope selectors:
- Products: Nearby / Wider Offline / Online
- Jobs: Nearby / City / State / India / Remote / Anywhere
- Services: Near me / Service radius / Wider area
- Rides: Route-based
- Finance/Insurance: Eligible providers / region availability

## Universal monetization attribution
User-facing comparison should remain useful and neutral. Revenue attribution happens in the backend.

Journey:
User need -> ASKODOX search/compare -> user selects -> tracked click/lead/deep link -> partner/provider -> conversion -> commission attribution -> ASKODOX revenue reporting.

Supported revenue sources can include:
- Affiliate/deep-link commerce commissions
- Insurance commissions
- Loan commissions
- Credit-card commissions
- Eligible partner/service commissions

Ranking must not simply prefer the highest ASKODOX commission. User relevance, price/value, eligibility, distance and fit stay primary. Sponsored/partner placements should be distinguishable when used.

## Home information hierarchy
1. Small mascot + ASKODOX AI
2. Ask bar with text/voice
3. Quick actions
4. Contextual compare card
5. Explore ASKODOX categories
6. How ASKODOX works / optional education card
7. Bottom navigation
